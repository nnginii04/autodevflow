# ADR-0004: 프로젝트 기록의 원본은 GitHub, 블로그는 종료 후 정리

- 상태: 채택
- 날짜: 2026-11-24

## 배경

계획, 진행, 결과물, 회고를 모두 기록하고 진행 이력을 증명할 수 있어야 합니다. 기록 채널로 GitHub와 블로그를 검토했습니다.

## 선택지

1. 블로그 중심: 판단 과정을 이야기로 전달하기 좋지만, 진행 이력의 증거로는 약함
2. GitHub 중심: 커밋, 이슈, PR, 태그가 시간과 함께 남아 진행 이력을 증명할 수 있음
3. 둘을 동시에 운영: 기록이 두 곳으로 나뉘고 관리 부담이 큼

## 결정

진행 중에는 GitHub에만 기록하고, 프로젝트가 끝나면 회고들을 바탕으로 블로그에 최종 정리 글을 씁니다.

## 이유

- 커밋 시간, 이슈, PR, Release는 사후에 꾸밀 수 없는 진행 기록입니다.
- 이 프로젝트의 주제가 산출물 간 추적성이므로, 프로젝트 기록 자체도 이슈, 커밋, 문서가 서로 추적되도록 운영합니다.

## 영향

- 판단 과정은 ADR(`decisions/`)과 회고(`retrospectives/`)에 남겨 블로그 글의 재료로 씁니다.
- 작업 규칙은 [docs/WORKFLOW.md](../docs/WORKFLOW.md)를 따릅니다.
