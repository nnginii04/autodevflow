# ADR-0002: 결정론적 처리를 우선하고 LLM은 의미 해석에만 사용

- 상태: 채택
- 날짜: 2026-11-24
- 관련: [docs/01-work-analysis.md](../docs/01-work-analysis.md) 8장

## 배경

모든 기능에 LLM을 적용하면 결과의 재현성과 신뢰성이 떨어지고 비용이 증가합니다. 자동차 개발처럼 검증 근거가 중요한 영역에서는 AI 판단과 도구 실행 결과를 구분해야 합니다.

## 선택지

1. 모든 분석을 LLM 에이전트에 맡김: 구현은 빠르지만 재현성, 비용, 근거 검증이 약함
2. 결정론적 도구 중심 + LLM은 필요한 단계에만: 구현량이 늘지만 판정 근거가 명확함

## 결정

2번을 채택합니다.

| 업무 | 방식 |
| --- | --- |
| 비정형 요구사항 추출, 변경 요청 구조화 | LLM |
| 모호성 분석, 의미적 모순 | LLM(관계 추출) + 규칙 엔진(판정) |
| ID 중복, 버전 일치, STALE 판정 | 일반 알고리즘 |
| 코드 구조, 코딩 규칙 | AST, 정적 분석 도구 |
| 추적 링크 후보 | BM25·임베딩 + AST·호출 그래프 + LLM 검증 |
| 승인된 링크의 영향도 | 그래프 탐색 |
| 시험 실행과 판정 | 시험 프레임워크 |
| 실패 원인 설명 | LLM + 실행 로그 |

## 이유

결정론적으로 처리할 수 있는 작업을 일반 소프트웨어로 구현하면 같은 입력에 같은 결과가 나오고, AI가 틀렸을 때 어느 단계에서 틀렸는지 추적할 수 있습니다.

## 영향

- LLM 출력은 확정 데이터에 직접 쓰지 않고 항상 PROPOSED 상태로 저장합니다.
- 근거가 없거나 존재하지 않는 코드 위치를 근거로 든 판정은 UNCERTAIN 또는 거부 처리합니다.
- 평가 시 LLM을 쓰지 않는 비교군(B0~B3)과 반드시 비교합니다.
